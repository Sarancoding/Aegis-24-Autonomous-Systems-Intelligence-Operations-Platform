# Financial Compliance Strategy

## Regulatory Framework

This document defines SEC/FINRA constraints for AI-generated financial reports and communications.

### 1. Prohibited Content

#### 1.1 Unlicensed Financial Advice
- **NEVER** provide specific investment recommendations (buy/sell/hold).
- **NEVER** suggest portfolio allocations or asset selection.
- **NEVER** predict price movements with certainty.
- **ALWAYS** include disclaimer: "This content is for informational purposes only and does not constitute financial advice."

#### 1.2 Guarantees & Promises
- **NEVER** guarantee returns, profits, or outcomes.
- **NEVER** use language like "will," "guaranteed," "certain," or "risk-free."
- **ALWAYS** use probabilistic language: "may," "could," "historically," "based on analysis."

#### 1.3 Insider Trading Signals
- **NEVER** act on or disseminate material non-public information (MNPI).
- **NEVER** process data sources known to contain MNPI.
- **ALWAYS** verify data sources are publicly available and legally obtained.

### 2. Required Disclosures

#### 2.1 Report Headers
Every financial report must include:
```
DISCLAIMER: This report is generated by an automated system for informational 
purposes only. It does not constitute investment advice, recommendation, or 
solicitation to buy or sell any security. Past performance is not indicative 
of future results. Consult a licensed financial advisor before making 
investment decisions.
```

#### 2.2 Data Source Attribution
- Cite all data sources with timestamps.
- Indicate data latency (real-time, delayed, end-of-day).
- Note any data gaps or quality issues.

### 3. Content Validation Rules

#### 3.1 Pre-Emission Checks
Before any financial content is emitted:
1. Scan for prohibited language patterns (guarantees, recommendations).
2. Verify disclaimer presence.
3. Validate data source citations.
4. Check confidence scores (escalate if < 0.8).

#### 3.2 Confidence-Based Escalation
- **Confidence >= 0.9**: Auto-emit with standard disclaimer.
- **Confidence 0.7 - 0.89**: Flag for human review before emission.
- **Confidence < 0.7**: Block emission, escalate to compliance officer.

### 4. Audit Trail Requirements

Every financial output must be traceable:
- **Trace ID**: Unique identifier linking output to input events.
- **Model Version**: LLM model and version used.
- **Prompt Hash**: SHA256 of input prompt for reproducibility.
- **Token Count**: Input/output token counts for cost attribution.
- **Timestamp**: UTC timestamp of generation.
- **Guardrail Decisions**: Log all guardrail checks and outcomes.

### 5. Violation Response

#### 5.1 Immediate Actions
If a compliance violation is detected:
1. **Block** the output immediately.
2. **Log** the violation with full context.
3. **Alert** the compliance team via Slack webhook.
4. **Quarantine** the generating agent for review.

#### 5.2 Remediation
- Analyze root cause (prompt injection, model drift, data contamination).
- Update guardrails to prevent recurrence.
- Re-train or fine-tune models if systematic issue detected.
- Document in `tasks/lessons.md`.

### 6. Periodic Review

- **Weekly**: Review escalated items and false positives.
- **Monthly**: Audit random sample of emitted content.
- **Quarterly**: Update compliance rules based on regulatory changes.
